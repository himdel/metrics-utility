# Newsletter 2026-10-26

Covers 2026-10-19 .. 2026-10-26 (4 metrics-utility commits, 7 metrics-service, 2 AWX commits touching models, neither a schema change).

## Changes

### ansible/metrics-utility

- `ansible/metrics-utility#617` - `main_host` and `main_host_daily` gain a nullable `first_automation` column, joined from `main_hostmetric` by hostname (AAP-96706). Both collectors are now version 1.1. Hosts with no host-metric row still appear, with NULL. Because the join is on hostname, a hostname that appears in several inventories gets the same value on every row.
- `ansible/metrics-utility#611` - reverts `ansible/metrics-utility#606`. The `events_table` and `main_jobevent_service` collectors no longer emit `collection_name`/`collection_version`, and the DB-backed test that came with them is removed. The PR gives no reason.
- `ansible/metrics-utility#608` - `Base.merge()` stops making two full DataFrame copies before `pd.merge`, which roughly halves the peak memory of each rollup merge (AAP-96713). It came from a 30-day CCSPv2 report that ran out of memory on about 550 MiB/day of job events. Output is unchanged.
- `ansible/metrics-utility#612` - the library README now lists all controller collectors, and shows `credentials_service`'s `since`/`until` signature.

### ansible/metrics-service

**Analytics API payload schemas.**
- `ansible/metrics-service#455` - the analytics rows API now has a typed OpenAPI schema for each collector's raw payload, selected by `collector`. It also fixes two serialization bugs: integer IDs in a window that contains NULLs were stored as floats (`31.0`), and date columns came out as midnight timestamps. The payload format changes visibly.
- `ansible/metrics-service#495` - `launched_by_username` is no longer stored in analytics payloads or anonymized rollups, so the analytics API stops returning it. The dashboard sync still gets it, because the leaderboards need it.
- `ansible/metrics-service#460` - the discovery endpoint now reports `payload_shape` (array or object) and `key_field` for each collector. Column exclusion now also applies to objects keyed by a data value, such as `instance_info` keyed by uuid.
- `ansible/metrics-service#497` - schemas brought back in line with metrics-utility devel: `first_automation` added to `main_host`/`main_host_daily`, and `collection_name`/`collection_version` dropped from the event collectors.

**Other.**
- `ansible/metrics-service#490` - analytics API requests are now counted per day, per endpoint and per status class, with no paths or users stored. The counts go into the daily anonymized Segment payload as `api_usage_telemetry`. This adds a new table, which follows the analytics retention policy (Controller `cleanup_jobs`, or 90 days).
- `ansible/metrics-service#482` - six helpers used only by their own tests were removed. This is the counterpart of `ansible/metrics-utility#613`, and it changes no behaviour.
- `ansible/metrics-service#478` - dashboard report test fixtures are now anchored at UTC midnight. CI used to fail when it ran between 01:00 and 02:59 UTC.

## Inconsistencies

- `ansible/metrics-utility#606` (per-event `collection_name`/`collection_version`) was reverted by `ansible/metrics-utility#611` nine days after it merged, and no reason was given.
- metrics-service's hand-written analytics schemas follow metrics-utility devel, not the release metrics-service locks (0.8.20260927, from before `ansible/metrics-utility#617`). With the locked version, the schema declares `first_automation` but the collector doesn't return it yet. Nothing keeps the two in sync except a docs note, and the schemas drifted within a day of `ansible/metrics-service#455`.
