# Newsletter 2026-11-02

Covers 2026-10-26 .. 2026-11-02 (8 metrics-utility commits, 10 metrics-service, no AWX schema changes).

## Changes

### ansible/metrics-utility

**Reports.**
- `ansible/metrics-utility#626` - new `build_report --format=ods` for CCSP, CCSPv2 and RENEWAL_GUIDANCE (AAP-75308). xlsx stays the default. It adds a runtime dependency on `odfpy~=1.4.1`, and files get a `.ods` extension. `--force` and the existing-file check apply to each format separately. Formulas are kept, with precomputed values. Internally, report builders now fill a format-neutral definition, and separate XLSX and ODS renderers write it out.
- `ansible/metrics-utility#605` - worksheet titles are now sanitized: invalid characters replaced, leading/trailing apostrophes and the reserved name `History` handled, truncated to Excel's 31-character limit, and given `~N` suffixes on collisions (AAP-96731). Before this, an org name over 31 characters made Excel show a repair dialog, and one containing `/` or `:` crashed report generation. A truncated per-org tab shows the full org name in row 1.
- `ansible/metrics-utility#618` - CCSPv2 now builds its host, event and collection-status DataFrames only when a sheet needs them, and frees each one after its sheets are written (AAP-96713). At 1M rows, peak memory dropped 17% (2724 to 2256 MB) and output is byte-identical. This follows `ansible/metrics-utility#608` and responds to customers hitting the 8 GiB limit.
- `ansible/metrics-utility#622` - if only the `jobs` or `infrastructure_summary` optional CCSPv2 sheet was selected, no input CSV was loaded and the sheet came out empty. Fixed, and single-sheet end-to-end tests were added. Default sheet sets were not affected.

**Collectors.**
- `ansible/metrics-utility#603` - five new organization-level collectors: `controller.unified_jobs_org`, `credentials_service_org`, `projects_by_scm_type_org`, `cred_type_counts_org` and `inventory_counts_org` (AAP-95739). The global collectors are unchanged, and rows with no organization go into their own unassigned group. Payload and identity rules are in `docs/org-aware-collectors.md`.

**Other.**
- `ansible/metrics-utility#620` - new `docs/data-lineage.md` and `docs/report-lineage.md` map each collector to anonymized metrics, the dashboard sync and report sheets, including each optional sheet's inputs. Writing these docs is what exposed the `ansible/metrics-utility#622` bug.
- `ansible/metrics-utility#613` - six unused helpers removed (`create_anonymized_object`, `BaseAnonymizedRollup.save_rollup`, `merge_by_name`, `S3Handler.get_s3_bucket`, `ManagementUtility.get_commands`, and the empty repo-root `__init__.py`). No behaviour change.
- `ansible/metrics-utility#623` - `cryptography` floor raised to `>=50.0.2`.

### ansible/metrics-service

**Analytics API.**
- `ansible/metrics-service#501` - `POST /api/v1/analytics/<collector>/collect/` is now idempotent per resolved UTC `(collector, since, until)` window (AAP-89143). Responses add `task_status` and `disposition` (`created`/`reused`/`requeued`). A request for a different window while one is already in flight for that collector returns 409. A disabled collector now returns 410 instead of 404. Failed or stale tasks are requeued, on-demand tasks run with `max_attempts=1`, and the task result includes `collection_id`.
- `ansible/metrics-service#504` - registers the five `controller.*_org` collectors from `ansible/metrics-utility#603` for on-demand analytics only (no cron, no anonymized rollups), with payload schemas and docs. The lockfile moves to metrics-utility 0.8.20261029.
- `ansible/metrics-service#506` - the registry drift test now only checks that every collector the service registers exists in metrics-utility, instead of requiring exact equality. New utility collectors can now merge before the service picks them up.

**Dashboard reports and leaderboard.**
- `ansible/metrics-service#499` - `JobData` now stores the Controller job type (AAP-93075). This adds migration `dashboard_reports/0004` with a `(job_type, finished)` index, plus a one-shot backfill task. Report list/details/export and the leaderboard accept a repeatable `?job_type=` (content-type names such as `job`, `systemjob`, `workflowjob`). The default is `job`, which also includes legacy rows not yet classified. This replaces the request-time AWX lookup from `ansible/metrics-service#486`, so the leaderboard's 503 response is gone, and runs of templates since deleted from AWX count again.
- `ansible/metrics-service#500` - new admin-only `PATCH /api/v1/dashboard_reports/template_metadata/` sets the two time-estimate fields on every template at once and returns `{"updated": n}`. Nulls are rejected.
- `ansible/metrics-service#489` - dashboard report endpoints now default `period` to `last_30_days` when it is missing or empty, instead of returning 400 (AAP-80902).

**Docs.**
- `ansible/metrics-service#502` - new `docs/report-recipes.md`: recipes that work with any BI tool for rebuilding the renewal guidance and CCSP/CCSPv2 reports from the raw analytics feeds.
- `ansible/metrics-service#498` - documents `api_usage_telemetry`. The endpoint label is the view name, so all collectors share one counter. A manual summary for a date past the retention window reads as zero usage.
- `ansible/metrics-service#503` - code comment now lists all six raw-only hourly collectors.
- `ansible/metrics-service#493` - aap-api-tests image digest bump.

## Inconsistencies

- `ansible/metrics-service#499` reverses `ansible/metrics-service#486` within a week: the job-template filter moves from a request-time AWX lookup to a stored `job_type`.
- metrics-service `pyproject.toml` still requires `metrics-utility>=0.8.0`, but since `ansible/metrics-service#504` it imports the `*_org` collectors, which exist only from 0.8.20261029. Only `uv.lock` was bumped, so an install that resolves an older metrics-utility fails with ImportError.
- metrics-service `docs/analytics.md` says a reused collect request returns 200 for a pending, running or completed task. The code and its OpenAPI schema return 202 while the task is pending or running, and 200 only once it has completed (`ansible/metrics-service#501`).
- Last week's schema drift should be resolved: metrics-service now locks metrics-utility 0.8.20261029, which postdates `ansible/metrics-utility#617`. The schemas are still kept in sync by hand.
