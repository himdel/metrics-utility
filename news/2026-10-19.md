# Newsletter 2026-10-19

Covers 2026-10-12 .. 2026-10-19 (2 metrics-utility commits, 11 metrics-service, 1 AWX schema-relevant).

## Changes

### ansible/metrics-utility

- `ansible/metrics-utility#606` - the `events_table` and `main_jobevent_service` job event collectors gain `collection_name` and `collection_version` columns per event (AAP-96707). The name is parsed from `resolved_action` in SQL with the same regex as the Python FQCN parser (a test keeps them aligned). The version is looked up in the job's `main_unifiedjob.installed_collections`. Both are NULL when they can't be determined, including events that only have a `task_action`. A revert is open as `ansible/metrics-utility#611`, see below.
- `ansible/metrics-utility#610` - AWX schema dump refreshed to f8314ad. The only DDL change is a nullable `object_ansible_id` on the two DAB RBAC role-assignment tables, which no collector reads.

### ansible/metrics-service

**Leaderboard (XLAB).**
- `ansible/metrics-service#486` - leaderboard metrics now count only runs of AWX job templates (no system jobs, ad-hoc runs or deleted templates), which the UI used to filter client-side (AAP-97385). The check reads the AWX DB on each request over its own connection with 5s timeouts, and the endpoint returns 503 if AWX is unreachable.
- `ansible/metrics-service#484` - each activity level now returns `current_user_runs`, the caller's own score (0 if none), so users outside the top 10 see their number as well as their rank (AAP-95619).
- `ansible/metrics-service#481` - ties within activity levels are now ordered by masked display name instead of AWX user id, which had made tied rows look unsorted (AAP-96077).

**URL prefix.**
- `ansible/metrics-service#468` - `URL_PREFIX` is now applied to every generated link: DRF absolute URLs, redirects, the Swagger schema URL and the OpenAPI path keys (`/api/v1/...` -> `/api/metrics/v1/...`). The committed schema keeps `/api/v1`, and the central spec sync publishes the prefixed paths. `tools/dev.sh --prefix` runs the mounted layout locally.
- `ansible/metrics-service#483` - tests bring `ServicePrefixMiddleware` to full branch coverage.

**Other.**
- `ansible/metrics-service#485` - urllib3 raised to `~=2.8` (CVE-2026-97687, CVE-2026-97689).
- `ansible/metrics-service#476` - GitHub workflow Postgres containers now pull from `mirror.gcr.io` because Docker Hub rate limits were breaking CI.
- `ansible/metrics-service#479` - the `collect_hourly_metrics` task metadata gains the missing `job_host_summary`, `unified_jobs_base` and `main_jobevent_legacy` examples.
- `ansible/metrics-service#459`, `ansible/metrics-service#487`, `ansible/metrics-service#491` - aap-api-tests image digest bumps.

### ansible/awx (database schema)

- `ansible/awx#16719` - no schema change, but the observable data changes. For `allow_simultaneous` templates, propagating a job's status to its parent template now uses `SELECT ... FOR UPDATE SKIP LOCKED`, so the update is silently skipped when another session holds the row. This fixes lock pile-ups (635+ queued sessions, UPDATEs taking 11-25 minutes). The cost: `current_job_id`, `last_job_id`, `last_job_failed` and `status` on `main_unifiedjobtemplate` (and the `main_jobtemplate` rows behind it) can point at an older job until that template's next status change.

## Inconsistencies

- `ansible/metrics-utility#606` merged on 2026-10-12, and a revert (`ansible/metrics-utility#611`) was opened the next day and is still open. Until that is settled, the new `collection_name` / `collection_version` event columns could disappear again.
- `ansible/awx#16719` vs our collectors: `unified_job_template_table` in metrics-utility reads `current_job_id`, `last_job_id`, `last_job_failed`, `last_job_run` and `status` straight from `main_unifiedjobtemplate`. Under concurrency on `allow_simultaneous` templates these can now be stale. Our code hasn't adapted. Anything that needs the true latest job should derive it from `main_unifiedjob` by `unified_job_template_id`.
- The leaderboard's ordering has changed twice: first by AWX user id, now (`ansible/metrics-service#481`) by masked display name. And with `ansible/metrics-service#486` it now depends on a live AWX DB connection at request time, which none of the other leaderboard inputs needed.
