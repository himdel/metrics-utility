# Newsletter 2026-09-29

Covers 2026-09-22 .. 2026-09-29 (11 metrics-utility commits, 6 metrics-service, 1 AWX schema-relevant).

## Changes

### ansible/metrics-utility

**Controller collectors consolidated.**
`ansible/metrics-utility#578` removes `library/collectors/awx/` (ported in `ansible/metrics-utility#573` last week) and folds it into `library/collectors/controller/`. Import paths are now `collectors.controller.*` only. Behaviour changes for consumers:
- `main_hostmetric` gather CSV bumps to version 1.1: it now includes hosts deleted during the window and adds `id` and `used_in_inventories` columns. The Renewal Guidance report re-filters deleted hosts in pandas, so its output is unchanged.
- Former `unified_jobs_table` callers now get `unified_jobs`' window (finished jobs only, sync jobs included), which is not the same row set as before.
- `ansible/metrics-utility#592` follows up: `query_info` accepts an (unused) `db=` argument so every collector metrics-service calls has the same signature.

**SQL helper functions now defer to AWX.** AWX creates `metrics_utility_parse_yaml_field` / `metrics_utility_is_valid_json` itself in migration `0212_create_metrics_utility_functions`.
- `ansible/metrics-utility#587` — `ensure_functions()` is now create-if-missing, so it no longer overwrites AWX's hardened definitions. Older Controllers still get the fallback, and that path still needs write access.
- `ansible/metrics-utility#577` — deletes the duplicate `tools/docker/functions.sql`. CI now surfaces psql import errors as non-fatal annotations.

Other changes:
- `ansible/metrics-utility#599` — fixes a `main_jobevent_service` crash when `event_data.ignore_errors` is a non-boolean string (e.g. an unrendered Jinja template). Unrecognised values now become false.
- `ansible/metrics-utility#589` — unit tests pin indirect-host dedup to `(hostname, organization)`.
- `ansible/metrics-utility#594` — the PR target check allows only `devel` and `stable-2.*` (matches metrics-service), so PRs against `stable-0.*` are rejected.
- `ansible/metrics-utility#595` — fixes `codecov.yml` nesting. The 1% project/patch thresholds were being ignored.
- `ansible/metrics-utility#591` — `make clean` tears down every compose profile in one pass. `ansible/metrics-utility#590` fixes copy-pasted script names in dev-script DB-not-ready messages.
- `ansible/metrics-utility#568` — monthly GitHub Actions bump, including majors: setup-uv 10, setup-python 7, create-github-app-token 3.

### ansible/metrics-service

**PostgreSQL client certificate auth (AAP-91529).**
- `ansible/metrics-service#428` — `default` and `awx` databases can authenticate with client certificates instead of a password, via the new `METRICS_SERVICE_DATABASES__<alias>__OPTIONS__{sslcert,sslkey,sslmode,sslrootcert}` env vars.
  - `PASSWORD` is required only when no cert pair is configured.
  - Startup rejects a half-configured pair, non-TLS `sslmode`, and uppercase OPTIONS keys.
  - The dispatcherd pg_notify connection now inherits the same TLS options.
  - README and `settings.local.py.example` are updated.
- `ansible/metrics-service#444` — `sslmode=prefer` is accepted after all, because the containerized installer generates it and startup was failing. `verify-full` is still recommended; the docs warn that `prefer` can fall back to plaintext.

**Gateway sync and `/users/me`.**
- `ansible/metrics-service#443` — `GET /api/v1/users/me/` gains `member_of_organizations: [{id, name}]`, built from locally synced RBAC data with no Gateway call per request. Superusers and auditors get `[]` unless explicitly assigned.
- `ansible/metrics-service#445` — `/users/me/` adds `is_system_auditor`. Other changes:
  - Gateway user/org/team/role sync now re-runs after every install or upgrade (keyed on a fingerprint of the service and DAB code) instead of only on first install.
  - Role assignments are replaced only from a complete Gateway snapshot, so a partial response can no longer delete valid assignments.
  - Incomplete runs fail and retry, and the sync task can no longer run twice at once.
- Two Tekton test-image digest bumps (`ansible/metrics-service#442`, `ansible/metrics-service#446`).

### ansible/awx (database schema)

- `ansible/awx#16660` — new data-only migration `0208_cleanup_orphaned_token_schedules` (RunPython, no DDL).
  - It deletes orphaned "Cleanup Expired OAuth 2 Tokens" schedules and NULLs stale `main_unifiedjobtemplate.next_schedule_id` references (a dependent table, but no column change).
  - Every later devel migration shifts up by one: skip_tags -> 0209, system_auditor -> 0210, the `main_host.last_job*` drop -> 0211, metrics-utility functions -> 0212.
  - Refer to these migrations by name, not number: the functions migration alone has been 0206, 0210, 0211 and now 0212.
