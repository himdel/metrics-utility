- **Upgrade pandas to 3.0 and openpyxl to 3.1.5** (ansible/metrics-utility#431) -- pandas 3.0 introduced a breaking change: missing values in string-typed columns are now `float('nan')` instead of `None`. This broke four code patterns across the codebase:
  - `extract_collection_name()` and `extract_role_name()` used `if x is None` identity checks -- replaced with `isinstance(x, str)`.
  - `renewal_guidance.py` join filter used `v is not None` -- same fix.
  - CCSP dedup logic treated `float('nan')` as truthy in `if serial:`, grouping all no-serial hosts into one bucket -- fixed with explicit `isinstance` guard.
  - Deprecated `'H'` frequency alias replaced with `'h'`.
  - Adds ~390 lines of regression tests (`DataframeMainJobevent` suite, two CCSP dedup tests).
  - Version pins: `pandas>=3.0.0`, `openpyxl>=3.1.5` in both `pyproject.toml` and `setup.cfg`.

### Inconsistencies and Notes

- **pandas 3.0 `NaN`-as-float is a user-facing risk**: The `isinstance(x, str)` guard pattern used throughout ansible/metrics-utility#431 is correct, but any downstream code or custom collectors that handle string columns from pandas DataFrames may hit the same breakage. The old `is None` / `is not None` pattern is now wrong for any pandas 3.0+ string column. Worth a note in user-facing docs or migration guide if users write custom collectors.
- **Dashboard removed then re-added in a different form**: ansible/metrics-service#253 deletes `apps/dashboard/` (Django app with session auth), and #254 adds a standalone HTML file with Basic auth. The old dashboard was production-facing; the new one is explicitly dev-only. If anyone was using the old dashboard endpoint in non-dev environments, they will lose it.
- **RBAC permission for tasks API may affect dev workflows**: #253 switches from `DeveloperModeRequired` to `IsSystemAdminOrAuditor`. The new standalone dashboard (#254) uses Basic auth, which works with RBAC. However, any existing dev tooling that relied on the `DEVELOPER_MODE_ENABLED` flag to access tasks endpoints will break.
- **Cross-repo CI is one-directional**: ansible/metrics-utility#427 runs service tests when utility changes, but there is no equivalent in metrics-service CI that tests utility changes. If the service makes assumptions about utility behavior, those are only caught when the utility CI runs.
