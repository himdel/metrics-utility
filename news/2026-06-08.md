- **Rename `FEATURE_ENABLED` to `FEATURE`, make feature flags env-var driven** (ansible/metrics-service#250) -- Major change to how feature flags work. The Dynaconf env var prefix is now shorter: `METRICS_SERVICE_FEATURE__<KEY>` (was `METRICS_SERVICE_FEATURE_ENABLED__<KEY>`). Feature flags are no longer pre-seeded into the DB by `init-default-settings`. Instead, flags resolve at runtime with three-tier precedence: DB row > env var > static default. The `init-default-settings` command becomes an upgrade hook that deletes redundant `true` DB rows (so env var overrides take effect), while preserving `false` rows (explicit opt-outs). The `DEFAULT_SETTINGS` dict, `--overwrite`, and `--all-known` CLI flags are removed as dead code. Touches ~20 files across code, tests, docker-compose, docs. This is the third name for this dict (`FEATURE_FLAGS` -> `FEATURE_ENABLED` -> `FEATURE`).

### Inconsistencies and Notes

- **Competing dashboard removal PRs**: ansible/metrics-service#252 (cshiels-ie) and ansible/metrics-service#253 (himdel) both remove the dashboard endpoint and switch the tasks API from dev-mode gate to RBAC permissions. #252 was opened first (Jun 5), #253 the day after (Jun 7). These look like they conflict -- one should probably be closed.
- **PR target branch validation is metrics-service only**: ansible/metrics-service#249 adds CI validation that PRs target `devel` or `stable-2.*`. metrics-utility has no equivalent check. Worth adding to metrics-utility for consistency, especially since it also uses `devel` as its default branch.
- **Feature flag naming: third iteration**: The settings dict was `FEATURE_FLAGS` (initial), then `FEATURE_ENABLED` (#36, to avoid AAP naming conflict), now `FEATURE` (#250, to shorten the env var prefix). Each rename touches many files and requires coordinated doc/config updates. The env var prefix breaking change (`METRICS_SERVICE_FEATURE_ENABLED__*` -> `METRICS_SERVICE_FEATURE__*`) will require operators to update their deployment configs.
- **`init-default-settings` semantics changed silently**: Before #250, `init-default-settings` created DB rows for feature flags. After #250, it deletes `true` rows and creates nothing. Existing deployment scripts or docs that expect rows to be created after running this command will see different behavior. The README was updated but downstream deployment playbooks may not be.
