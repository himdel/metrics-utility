## Inconsistencies

- **`ensure_functions()` can silently downgrade AWX's hardened SQL functions.** `ansible/awx#16458` makes AWX own `metrics_utility_is_valid_json` and `metrics_utility_parse_yaml_field` in a newer, hardened form (escaped field name, narrow `invalid_text_representation` catch). Our `library/collectors/util.py::ensure_functions()` still issues `CREATE OR REPLACE` with the older bodies (unescaped field, bare `WHEN others`) and is called by the `main_host`, `job_host_summary` and `main_hostmetric` collectors. Against an AWX >= 0211 database with write access, it overwrites the newer definitions — `CREATE OR REPLACE` does not check which is newer. This should become version-aware or be dropped.
- **Three copies of those functions now exist**, and AWX's is the newest: AWX migration 0211, `tools/docker/functions.sql` (stale), and `ensure_functions()` (stale). In CI, `latest.sql` now carries AWX's versions and `functions.sql` then fails "already exists" — swallowed only because neither loader sets `ON_ERROR_STOP`. Open PR `ansible/metrics-utility#577` is the right fix for the CI half.
- **The AWX >= 0211 `GRANT ... TO PUBLIC` obsoletes our "readonly DB cannot use ensure_functions" caveat** in the collectors. That comment no longer holds on current AWX.
- **Same repo-sync bug fixed two different ways in the same day.** `ansible/metrics-utility#586` guards on `github.repository_owner == 'ansible'`; `ansible/metrics-service#433` guards on `github.repository == 'ansible/metrics-service'`, hardcoding its own repo name into a workflow that is otherwise deliberately repo-name-agnostic. This belongs in the shared `ansible-cicd` template.
- **Action-version drift in the two mirrored copies of that workflow**: metrics-service is on `actions/create-github-app-token@v3`, metrics-utility appears to still be on v2.
- **Indirect node collection defaults now diverge across repos.** metrics-service's `INDIRECT_NODE_COLLECTION=True` (`ansible/metrics-service#413`) was not reverted, while metrics-utility's equivalent defaults were. The two are independent code paths so nothing is broken, but "on by default" now holds only on the metrics-service side.
- **A refactor died in the revert chain.** `ansible/metrics-utility#559` bundled a policy flip, a de-duplication refactor and a feature. Reverting the policy killed all three; the feature was re-landed as `ansible/metrics-utility#584`, but `build_report.py` and `validation.py` each hold their own copy of the default sheet list again, and `validate_collectors()` has re-acquired the getter/validator drift that `ansible/metrics-utility#560` had fixed.
- **Latent, unfixed**: `ansible/metrics-utility#566` documents that host collectors guard with a `json` cast then extract with `::jsonb`. No commit in this window fixes it.
