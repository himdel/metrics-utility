# Newsletter 2026-10-12

Covers 2026-10-05 .. 2026-10-12 (1 metrics-utility commit, 10 metrics-service, 0 AWX schema-relevant).

## Changes

### ansible/metrics-utility

- `ansible/metrics-utility#602` - `dashboard_jobs` now returns `organization_name` (LEFT JOIN on `main_organization`, null for jobs without an org). Before this, jobs from the initial dashboard backfill reached `JobData` with no org name. The hourly `unified_jobs_dashboard` path already returned it. Service-side counterpart: `ansible/metrics-service#470`.

### ansible/metrics-service

**Leaderboard (XLAB).**
- `ansible/metrics-service#470` - a new one-shot `backfill_dashboard_organization_names` system task fills in `JobData.organization_name` on rows the initial backfill left empty. It runs in batches (`batch_size`, default 5000) and is safe to run alongside the hourly sync. The leaderboard and `active_organizations` now skip orgs with no name.
- `ansible/metrics-service#474` - org achievements (`sustained`, `rising`) are now evaluated across every member org of the caller and combined, not just the busiest one. `top_tier` still uses the best rank.
- `ansible/metrics-service#473` - OpenAPI fix: `org_streak.organization` is now really nullable. Before, it was emitted as `allOf` + `nullable`, which OpenAPI 3.0 validators ignore. The `OrgStreakOrganization` component is gone from the committed schema. A new test validates sample responses against the generated schema.
- `ansible/metrics-service#471` - the daily anonymized payload gains `leaderboard_telemetry` (`enabled`, `observed_at`), which reports whether `SHOW_LEADERBOARD` is on. If the setting can't be read it is reported as `enabled: null` rather than the default.
- `ansible/metrics-service#469` - `collection_status.last_sync` now also counts the completed initial collection, so installs with no hourly sync yet no longer report null. This needed two task-system fixes:
  - `init-system-tasks` no longer wipes `completed_at` on completed one-shot tasks.
  - Task cleanup (the periodic task and the API action) no longer deletes completed one-shots. Deleting them made those tasks run again.

**BYO-BI analytics (ANSTRAT-1587) follow-ups.**
- `ansible/metrics-service#451` - when `analytics_retention_days` is not passed, analytics payload retention now follows the Controller `cleanup_jobs` schedule, read on every run, falling back to 90 days. An explicit value still overrides it and is now validated. The code is now shared with dashboard retention in `apps/tasks/retention.py`. Analytics retention is not gated by `USE_CONTROLLER_RETENTION`.
- `ansible/metrics-service#467` - `AnalyticsPayload` gains a nullable `cluster_id` (Controller `INSTALL_UUID`), exposed in the rows API. New migration `analytics/0002`. If the lookup fails the payload is still stored.
- `ansible/metrics-service#466` - more collectors enabled for analytics: `controller.main_indirectmanagednodeaudit`, `controller.unified_jobs` (`unified_jobs_base`), `controller.main_jobevent` (`main_jobevent_legacy`), and `controller.job_host_summary` (needs metrics-utility's PostgreSQL helper functions). The registry now has only two tiers, ENABLED and NOT ENABLED.
- `ansible/metrics-service#462` - `collect_analytics_on_demand` and raw-only collectors now fail when the payload can't be stored, instead of reporting success with nothing saved.
- `ansible/metrics-service#461` - collector output is converted to valid JSON recursively before it is stored: Decimal and NumPy values are converted, and NaN/inf become null. The trigger was `controller.instance_info` crashing on save.

## Inconsistencies

- `ansible/metrics-service#470` replaces the NULL-last org tie-break from `ansible/metrics-service#435`: orgs with no name are no longer ranked at all.
- `ansible/metrics-service#474` reverses part of `ansible/metrics-service#457`: org achievements no longer come only from the caller's busiest org. `org_streak` still does.
- Cross-repo: metrics-service's `uv.lock` still pins metrics-utility `0.8.20260927`, which predates `ansible/metrics-utility#602`. Until the lock is bumped, new installs keep writing initial-backfill jobs without an org name, and `ansible/metrics-service#470` hides those orgs from the leaderboard.
