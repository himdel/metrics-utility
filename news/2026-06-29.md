# Newsletter 2026-06-29

## Changes

### ansible/metrics-utility

- Indirect managed nodes anonymized rollup: redesigned to use `IndirectManagedNodesAnonymizedRollup` model with field renames (`org_id` -> `organization_id`, etc.), added `unique_managed_hosts` dedup and `host_metric_summary_monthly` table integration (ansible/metrics-utility#453, ansible/metrics-utility#457)
- Filter option collectors for AWX orgs, templates, projects, and labels -- new collector family that fetches picklist data for dashboard dropdowns (ansible/metrics-utility#455)
- Events perf test tooling: `run.py` now runs events collector, adds `--limit` flag and richer fixture data for benchmarks (ansible/metrics-utility#451)
- `cleanup_glob` fix: outlier test fixtures were not being cleaned up, missing cleanup pass added (ansible/metrics-utility#450)
- Mock Prometheus server (Go binary) added for vCPU collector integration tests -- replaces coupling to a live Prometheus instance (ansible/metrics-utility#432)
- Compose environments merged: separate podman/docker Makefile targets consolidated into unified `docker-compose.yml` with profile-based service selection (ansible/metrics-utility#433)
- Candlepin functionality disabled by default (`CANDLEPIN_ENABLED` now defaults to `False`), reversing the default-on from ansible/metrics-utility#363 (ansible/metrics-utility#460)
- PR target repo/branch validation CI check added -- blocks PRs accidentally targeting forks instead of upstream (ansible/metrics-utility#458)
- Jira ticket tagging GitHub Action added for automatic PR-to-Jira linking (ansible/metrics-utility#462)
- SonarCloud scan action bumped from 7.2.1 to 8.2.0 (ansible/metrics-utility#393)

### ansible/metrics-service

- Prometheus endpoint secured: moved from unauthenticated `/metrics` to `/api/metrics` behind DRF auth, fixing AAP-77819 (ansible/metrics-service#251)
- Events collector re-enabled with resource limits (`EVENTS_COLLECTOR_MAX_JOBS`, `EVENTS_COLLECTOR_MAX_ROWS`) after being disabled due to OOM risk (ansible/metrics-service#295, ansible/metrics-service#300)
- Indirect managed nodes: hourly collector task added, anonymization support, dedicated `INDIRECT_NODE_COLLECTION_GROUP` task group extracted from general collection (ansible/metrics-service#274, ansible/metrics-service#296, ansible/metrics-service#301)
- Dashboard collection enabled by default (`DASHBOARD_COLLECTION` flag promoted from opt-in to default-on), plus telemetry self-observability for collection duration/record counts (ansible/metrics-service#275, ansible/metrics-service#269)
- Custom date range filter for automation dashboard reports -- `date_from`/`date_to` query params with validation (ansible/metrics-service#272)
- Incremental `JobHostSummary` sync via `job_host_summary_service` post-collect hook, replacing full-table reload (ansible/metrics-service#285)
- Job label sync: labels now synced from AWX and exposed as `label_ids` in report responses (ansible/metrics-service#306)
- Platform auditors granted read access to `collection_status` endpoint via `IsPlatformAuditor` permission class (ansible/metrics-service#302)
- Task startup fix: AWX DB readiness check added to prevent tasks from failing when AWX migrations haven't completed yet (ansible/metrics-service#280)
- pytz fully removed, replaced with stdlib `datetime.UTC` / `datetime.timezone.utc` (ansible/metrics-service#297, ansible/metrics-service#298)
- Standalone docker-compose removed, unified compose from metrics-utility adopted (ansible/metrics-service#266)
- GitHub Actions pinned to commit SHAs with version comments (ansible/metrics-service#283)
- CI: sonar/codecov steps now skip gracefully when secrets are missing (fork PRs), with fix for `if:` condition syntax (ansible/metrics-service#303, ansible/metrics-service#305)
- Jira PR auto-linking GitHub Action added, with iterative fixes for token, whitespace, and backtick issues (ansible/metrics-service#304, ansible/metrics-service#308, ansible/metrics-service#309, ansible/metrics-service#310)

### ✨ ansible/awx (database schema)

- `main_host.last_job_id` and `main_host.last_job_host_summary_id` are no longer written to -- bulk updates removed due to 75-second median query time at scale. Columns remain but are now stale. **Our collectors may be affected** if they derive `last_automation` dates from `main_host.last_job_id` (ansible/awx#16332)
- Workload identity credentials: new `internal: true` attribute in `main_credentialtype.inputs` JSON schema, gated by `FEATURE_OIDC_WORKLOAD_IDENTITY_ENABLED`. No structural column change but the JSON shape has expanded (ansible/awx#16286, ansible/awx#16348)
- Migration 0204 data fix: credential type rename was filtering by non-unique `kind` field instead of unique `namespace`, risking incorrect row updates

## Inconsistencies

- `main_host.last_job_id` is now stale in AWX (ansible/awx#16332) but our metrics-utility collectors may still read it for `last_automation` dates -- needs audit before the column is dropped in a future AWX migration.
- Candlepin was enabled by default in ansible/metrics-utility#363, then disabled by default one month later in ansible/metrics-utility#460 -- the feature was not ready for general use. If any deployment had it on, they need to explicitly set `CANDLEPIN_ENABLED=True` to keep it.
