# Newsletter 2026-08-03

## Changes

### ansible/metrics-utility

- Ruff bumped from 0.9.2 to 0.16.0, switched from `extend-select` to explicit `select` with 20 rule groups; CI now uses `uv run ruff` instead of `uvx ruff` (ansible/metrics-utility#506)
- Fixed CLI indirect-nodes collector regression: restored `daily_slicing` mode and `since`/`until` passthrough that were lost when the collector was refactored in ansible/metrics-utility#475 (ansible/metrics-utility#508)
- Segment message limit restored to 32KB (from the conservative 16KB cut in ansible/metrics-utility#281); header overhead is now calculated dynamically by building a representative header via `_build_properties()`, with chunk size guards to prevent oversized payloads (ansible/metrics-utility#510)

### ansible/metrics-service

- Reverted both pyasn1 pins (ansible/metrics-service#372, ansible/metrics-service#373) -- the `~=0.6.4` and `>=0.6.4` pins from ansible/metrics-service#368 and ansible/metrics-service#369 were both backed out on the same day, removing the explicit pin entirely
- Enabled ordering by "Time saved" column on the automation savings summary endpoint (ansible/metrics-service#371)
- Added missing "Time Saved (hours)" column to CSV summary export (ansible/metrics-service#374)
- Fixed ROI manual execution time calculation: removed an artificial 30-minute floor that inflated time estimates for short jobs (ansible/metrics-service#375)
- Major task retry refactor: moved retry logic from execution-time (`execute_db_task`) to the scheduler's periodic sync via `_retry_failed_tasks()`; `Task.retry()` is now a pure atomic state writer (sets status/increments attempts/clears error in one `.save()`), `submit_task_to_dispatcher` no longer sets task status on error, and CLI/API submit paths consolidated (ansible/metrics-service#355)

### ansible/awx (database schema)

- No schema changes this week. The one commit in scope (ansible/awx#16564 -- prefer `scm_revision` as `cache_id`) only changes Python property logic.

## Inconsistencies

- The pyasn1 pin cycle (add in ansible/metrics-service#368, fix in ansible/metrics-service#369, revert both in ansible/metrics-service#372 and ansible/metrics-service#373) suggests the underlying issue is unresolved or was fixed differently upstream. Worth confirming pyasn1 compatibility is stable before the next release.
- The ansible/awx#16568 open PR adds migration 0208 changing `update_cache_timeout` on `main_inventorysource` to allow negative values. This table is not in our direct collector dependency list, but if inventory source metadata is ever collected in the future, the new `-1` sentinel value would need handling.
