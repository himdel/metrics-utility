# Newsletter 2026-11-09

Covers 2026-11-02 .. 2026-11-09 (9 metrics-utility commits, 12 metrics-service, no AWX schema changes).

## Changes

### ansible/metrics-utility

**Reports.**
- `ansible/metrics-utility#619` - CCSP DataFrames now store six low-cardinality string columns (`install_uuid`, `organization_name`, `job_template_name`, `module_name`, `collection_name`, `role_name`) as categoricals, and standard mode drops the always-empty `host_names_before_dedup` column (AAP-96713). With `ansible/metrics-utility#618`, peak memory at 1M rows is down 24% (2724 to 2078 MB) and runtime 953 to 844 s. Output is identical.
- `ansible/metrics-utility#609` - the report builder makes fewer DataFrame copies (AAP-96713). Host-name lookup keys are built vectorized instead of per row, the input frame is no longer mutated, and the Inventory Scope sheet copies only the columns it uses. Review caught a null-key regression (`astype(str)` keeps NaN, which would have undercounted hosts) before merge.

**Collectors.**
- `ansible/metrics-utility#580` - Segment events from `StorageSegment` now carry `properties.version`, default `"v1"`, which callers can override through `segment_meta['version']` (AAP-98018).

**Dependencies.**
- `ansible/metrics-utility#632`, `ansible/metrics-utility#634` - sqlparse moved to 0.6.1 for CVE-2026-112307. #632 added a direct `sqlparse==0.6.1` dependency, and #634 removed it again once the product container enforced the floor. `uv.lock` still resolves 0.6.1 through Django.
- `ansible/metrics-utility#627` - monthly dependabot batch (7 updates).

**CI.**
- `ansible/metrics-utility#630` - AWX schema extraction, PyPI publishing, Snyk and SonarCloud now run only in the `ansible` org. In the downstream mirror, Jira PR linking and schema review still run for PRs against `stable-2.x`.
- `ansible/metrics-utility#631` - Sonar is skipped when its token or its coverage/PR-number artifacts are missing. This ports the pattern from `ansible/metrics-service#514`.
- `ansible/metrics-utility#629` - the AWX schema workflow is pinned to Python 3.14 because AWX's `hiredis==3.2.1` fails to build on 3.15. The pin is marked temporary.

### ansible/metrics-service

**RBAC.**
- `ansible/metrics-service#516` - role definitions and their assignments now sync from Gateway, for example Controller "Organization Audit" and EDA "Organization Auditor" (AAP-100995).
  - `GET /api/v1/role_user_assignments/` and the team equivalent used to return 500 once any user held a role. Fixed.
  - `/users/`, `/teams/` and `/organizations/` gain a `resource` filter.
  - `initial_resource_sync` re-runs once on deploy.
- `ansible/metrics-service#509` - django-ansible-base 2026.10.26 and DRF 3.18.2 (DRF CVE-2026-114136/7/8). DAB adds bulk endpoints (`resources/bulk-update/`, `role-{user,team}-assignments/bulk-{assign,unassign}/`). Nested role-assignment routes are now paginated list operations, so some OpenAPI `operationId`s changed. This matters for anyone generating clients from the spec.

**Dashboard reports.**
- `ansible/metrics-service#526` - new read-only `GET /api/v1/dashboard_reports/template_metadata/defaults/` returns the UI's default time estimates, `{manual: 30, create_automation: 60}`, for admins and auditors (AAP-101269).
- `ansible/metrics-service#537` - `sync_dashboard_job_records` and the sync hook were split into helpers to bring Sonar cognitive-complexity ratings down. No intended behaviour change.

**Analytics and tasks.**
- `ansible/metrics-service#517` - every analytics payload field and every rows/discovery/collect serializer field now has a description, and the committed OpenAPI spec was regenerated. A test fails on any undocumented field. The docs counterpart is `ansible/aap-docs#6111`.
- `ansible/metrics-service#518` - the `awx_database` task parameter is gone: Controller-backed tasks always read the `awx` alias. Existing tasks that still carry `awx_database` or `database` kwargs log a warning and keep running.
- `ansible/metrics-service#513` - task metadata examples added for the five `*_org` collectors from `ansible/metrics-utility#603`, and an unsupported database-alias example removed.

**CI and tooling.**
- `ansible/metrics-service#514` - the Sonar `workflow_run` job is skipped when Dependabot or fork PRs leave no coverage artifacts, instead of failing.
- `ansible/metrics-service#524` - Sonar rating raised to B+ (AAP-101208). Repeated payload-schema description strings became constants.
- `ansible/metrics-service#519` - `make generate-openapi-schema` and the README now run `tools/generate-openapi.sh`, same as CI. The old inline spectacular calls skipped the script's patches.
- `ansible/metrics-service#510` - monthly dependabot batch (4 updates). `ansible/metrics-service#508` - aap-api-tests image digest bump.

## Inconsistencies

- `ansible/metrics-service#516` brings back the `RoleDefinition` resource registration that the DAB retrofit (`ansible/metrics-service#73`, `ansible/metrics-service#75`) removed, now as shared and pull-only.
- Analytics payload field descriptions (`ansible/metrics-service#517`) live only in metrics-service's hand-written payload schemas. metrics-utility collectors carry none, so every metrics-utility column change now also needs a description added on the metrics-service side. The new test only fires once someone adds the field there.
- `ansible/metrics-service#526` serves a 30-minute default for manual time per template, but dashboard sync still estimates manual time as 2x the job's elapsed time. The two can disagree for the same template.
- The sqlparse CVE fix went from a lockfile-only floor (`ansible/metrics-utility#564`) to a direct `==` pin (`ansible/metrics-utility#632`) and back (`ansible/metrics-utility#634`) within a week.
- The Sonar artifact-skip workflows are now in both repos but not identical: metrics-utility's port (`ansible/metrics-utility#631`) also gates the scan step on the token. Minor, but worth syncing if `sonar_checks.yml` is meant to be shared.
