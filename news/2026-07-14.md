# Newsletter 2026-07-14

## Changes

### ansible/metrics-service

- ansible/metrics-service#336 -- bump PyJWT to 2.13.0 to fix security vulnerability (AAP-78015)
- ansible/metrics-service#337 -- fix pagination and ordering in automation dashboard: DAB's `DefaultPaginator` was ignoring `PAGE_SIZE` from `REST_FRAMEWORK` settings; fix by setting `page_size` directly on the paginator class
- ansible/metrics-service#338 -- fix report validation when saving with a duplicate name: validation moved to serializer level to return proper 400 instead of unhandled IntegrityError
- ansible/metrics-service#343 -- guard `DYNACONF._post_hooks` access to prevent `AttributeError` when hooks haven't been initialized yet
- ansible/metrics-service#335 -- move `indirect_managed_nodes` example from `collect_hourly_metrics` metadata to `collect_daily_metrics` where it actually belongs after the pipeline move
- ansible/metrics-service#279 -- switch some exception handlers from `logger.error()` to `logger.exception()` for automatic traceback capture; disable SonarQube rule python:S8572 that would force this everywhere
- ansible/metrics-service#341 -- revert Renovate cron fix from ansible/metrics-service#324: Renovate actually requires wildcard minutes (`* */6 * * *`), fixed minutes break it
- ansible/metrics-service#340 -- hardcode dashboard collection retention to 90 days instead of deriving from Controller's cleanup schedule; Controller setting still available as opt-in override
- ansible/metrics-service#317 -- make `tools/dev.sh` compatible with macOS bash 3.2 by replacing `wait -n` and `declare -A` with POSIX-compatible alternatives
- ansible/metrics-service#320 -- one-time resource sync of users and RBAC assignments from gateway on service init (AAP-80890); uses `RESOURCE_SERVER` URL from Dynaconf to pull users/teams/orgs and map RBAC
- ansible/metrics-service#346 -- remove remaining Celery references from `.gitignore` (celerybeat files); Celery-to-dispatcherd migration is now fully complete

### ansible/metrics-utility

- ansible/metrics-utility#461 -- add AWX schema extraction script and weekly CI workflow; two-job split (low-privilege extract + high-privilege create-pr) for security; strips pg-version-dependent output for stable diffs
- ansible/metrics-utility#477 -- add `OperationalError` propagation test for indirect node collector, documenting the intentional asymmetry: `ProgrammingError` is caught for AAP 2.4 graceful degradation, but `OperationalError` propagates
- ansible/metrics-utility#478 -- extend perf test tooling with indirect managed node audit data: batch insert of 500 records, FK-aware deletion order, collector docstring clarification on optional since/until params

### ansible/awx (database schema)

- ansible/awx#16530 -- migration 0206 adds composite index `main_jobhostsumm_host_id_desc` on `main_jobhostsummary(host_id, id DESC)`; makes the `with_latest_summary_id()` subquery efficient after `last_job_host_summary_id` deprecation. `main_jobhostsummary` is one of our dependent tables -- index-only, no column changes.

## Inconsistencies

- Dashboard retention policy reversed direction: ansible/metrics-service#319 (last week) derived retention from Controller's `cleanup_jobs` schedule, but ansible/metrics-service#340 (this week) hardcodes it to 90 days with Controller as opt-in override. The learnings arc now shows three approaches tried across 4 PRs.
- The AWX `last_job_host_summary_id` deprecation continues: ansible/awx#16530 adds the replacement index, reinforcing that our collectors should not rely on `Host.last_job_host_summary_id`. Our code doesn't currently use it, so no action needed, but worth tracking if the column is eventually dropped.
